## 1. Purpose
Describes the V2 horizon — "Assistance & Insight" — building on the V1 continuous record with educational AI, prediction, caregiver sharing, and richer guided modules. All V2 capability remains within the non-goals (no diagnosis/prescription/emergency decisions).

## 2. Scope
V2 themes and their entry gates. Detailed designs already exist in module/AI docs (V2 is largely "turn on" of specified-but-deferred features).

## 3. V2 Capabilities
- **Educational AI assistant** (`docs/06-Modules/94`, `docs/07-AI/*`): explain reports, summarise visits, surface trends and missing data, generate reminders — guardrailed, typed, sourced.
- **Prediction engine** (`docs/07-AI/104`): weight-gain/BP/growth trajectory surfacing — non-diagnostic.
- **Caregiver / family sharing** (`docs/06-Modules/96`) if deferred from V1.
- **Guided nutrition & exercise** (`docs/06-Modules/86`, `87`): programmes (still educational).
- **OCR report extraction** (`docs/07-AI/106`): user-reviewed.
- **Richer journal/feeding/sleep analytics** (surfacing).

## 4. Entry Gates
- **AI guardrails pass** (MS-2.1: 0 diagnostic/prescriptive/emergency outputs) before any AI ships (`docs/07-AI/105`, `docs/10-Testing/135`).
- V1 continuity/privacy/accessibility gates green (`docs/01-Product/16`).
- Provider DPA + consent flows in place for AI/OCR (`docs/09-Security/126`).

## 5. Business Rules
- BR-1 V2 stays within non-goals (no diagnosis/prescription/emergency decisions).
- BR-2 AI/prediction ship only after guardrail conformance.
- BR-3 V2 preserves V1 continuity/privacy invariants.
- BR-4 New processing (AI/OCR) requires consent + DPA + minimal PHI.
